# Plan: consolidate per-environment JSON settings into a single TOML file

## 1. Objective

- Replace the `config/<env>.json` fan-out with a single `config/settings.toml` keyed by environment section, so settings live in one place that diffs cleanly and supports comments.
- Ship one release of backwards-compat: if the legacy JSON files are present, read them and emit a single deprecation warning per process. Remove the shim next release.
- Give operators a `--dump-config` CLI flag that prints the merged, resolved config for the active environment, so debugging "what did the app actually load?" stops requiring a REPL.

Non-goals:

- Schema validation / pydantic models — settings stay as plain dicts for now.
- Secret management — env-var overrides and secret backends are out (tracked in ROADMAP under "config: secrets").
- Hot-reload — load-once-at-startup remains the model.

## 2. Approach

**Strategy: introduce a single `load_settings(env)` loader that prefers `config/settings.toml` and falls back to legacy JSON with a deprecation warning; layer a defaults section under the env-specific section via deep merge.**

Why this shape:

- One loader, one source of truth, one fallback path — the backwards-compat surface is contained to a single function so the next release can delete one branch.
- Deep merge (not replace) lets `[default]` carry shared keys and each `[env]` override only what differs — matches how the JSONs are used in practice today.

Specific mechanics:

- **Parser**: stdlib `tomllib` (Python 3.11+, read-only, no extra dep). Files written by humans, never by the loader, so no writer needed.
- **File shape**: `[default]` table holds shared keys; `[dev]`, `[staging]`, `[prod]` override. Loader returns `deep_merge(data["default"], data[env])`.
- **Deep merge**: dict-of-dicts recursive merge; non-dict values from `env` replace `default`; lists replace (do not concat) — matches JSON semantics today.

  ```python
  def deep_merge(base: dict, overlay: dict) -> dict:
      """Recursive dict merge. overlay wins; lists/scalars replace."""
  ```

- **Fallback trigger**: if `config/settings.toml` is missing AND `config/<env>.json` exists, load the JSON and warn:

  ```python
  warnings.warn(
      "config/<env>.json is deprecated; migrate to config/settings.toml. "
      "Run `python -m myapp.config.migrate` to convert. "
      "JSON support will be removed in the next release.",
      DeprecationWarning,
      stacklevel=2,
  )
  ```

  Warning fires once per process via a module-level flag (not `simplefilter`, which is global state).

- **If both exist**: TOML wins, JSON is ignored silently — avoids cron-job warning spam after the operator has migrated but forgot to delete the old files. Document this in the migration script's output.
- **Migration script**: `python -m myapp.config.migrate` reads each `config/<env>.json`, computes the `[default]` table as the intersection of common keys with identical values across all envs, writes `config/settings.toml`. Leaves the JSONs in place; operator deletes them after verification.
- **Sample target TOML** (shape only):

  ```toml
  [default]
  log_level = "INFO"
  db_pool_size = 5

  [dev]
  db_url = "postgres://localhost/myapp_dev"
  log_level = "DEBUG"

  [prod]
  db_url = "postgres://prod-db/myapp"
  db_pool_size = 20
  ```

- **`--dump-config` CLI**: prints the resolved merged dict for the active env as TOML (round-trippable) to stdout, exits 0. Uses `tomli_w` (small dep) OR formats as JSON if avoiding the dep matters — defaulting to JSON output since stdlib has `json.dumps` and the dump is for human/`jq` consumption, not re-loading.

Scope IN:

- `config/settings.toml` becomes the canonical source.
- `myapp/config/loader.py` — new loader with fallback.
- `myapp/config/migrate.py` — one-shot migration script.
- `--dump-config` flag wired into the existing CLI entry point.
- Tests for: TOML load, deep merge, JSON fallback + warning, both-present precedence, dump output shape.

Scope OUT:

- Removing the JSON fallback (next release; tracked as TODO in `loader.py` referencing the version bump).
- Schema validation (ROADMAP: "config: typed schema").
- Secrets / env-var overrides (ROADMAP: "config: secrets").
- Migrating CI/deploy pipelines that write `config/<env>.json` — operator task, called out in the deprecation warning text.

Delivery: one PR, one commit on branch `config/toml-consolidation`. Solo.

Done when: `pytest -q` passes, `python -m myapp --env=prod --dump-config` prints merged prod settings, deleting `config/settings.toml` and re-running prints the same output with a single `DeprecationWarning` on stderr.

## 3. Per-change overview

### 3.1 `config/settings.toml` (new, replaces JSONs)

- Single TOML file with `[default]` + one table per env.
- Generated by running the migration script against the current JSONs; hand-edited afterward to tidy the `[default]` extraction.
- Committed to the repo; legacy `config/*.json` stay committed for one release to keep rollback trivial.

### 3.2 `myapp/config/loader.py` (new)

- Exposes `load_settings(env: str) -> dict`.
- Resolution order: TOML present → use it; else JSON present → use it + warn; else raise `FileNotFoundError` with both paths in the message.
- Module-level `_warned: set[str]` so the deprecation fires once per env per process.
- Exposes `deep_merge(base, overlay)` for reuse by the dump command.

### 3.3 `myapp/config/migrate.py` (new, one-shot)

- `python -m myapp.config.migrate` entry point.
- Reads all `config/*.json` it finds, factors out the `[default]` table (keys present with identical values in every env), writes `config/settings.toml`.
- Refuses to overwrite an existing TOML unless `--force` is passed.
- Prints a short summary: files read, default keys extracted, where to delete the JSONs after verifying.

### 3.4 CLI: `--dump-config` flag

- Added to the existing CLI argparse/click setup (whichever the project uses — wire into the same entry point as `--env`).
- Calls `load_settings(env)`, dumps as JSON to stdout (pretty-printed, sorted keys), exits 0.
- Honors the same `--env` flag the app uses for normal runs, so "what config does prod see?" is one command.

### 3.5 Call sites for old config loading

- Find every `json.load(open("config/<env>.json"))` (or equivalent helper) and route through `load_settings(env)`.
- Likely one or two helpers — the loader is the indirection; call sites stop knowing about file format.

### 3.6 Tests: `tests/test_config_loader.py` (new)

- TOML-only path: returns merged `[default]` + `[env]`.
- JSON-only path: returns JSON dict and emits exactly one `DeprecationWarning`.
- Both-present path: TOML wins, no warning.
- Missing both: `FileNotFoundError` mentions both paths.
- Deep merge: nested dicts merge, lists replace, env scalar overrides default scalar.
- Migration script: round-trips a fixture set of JSONs → TOML → loader returns equivalent dict per env.

### 3.7 Docs

- `README.md` (or `docs/configuration.md` if one exists): document the TOML layout, the `--dump-config` flag, and the one-release deprecation window with the exact removal version.
- `CHANGELOG.md`: entry under the next version — "config: TOML consolidation, JSON deprecated, removal in vN+1."

## 4. Implementer guide

### Step 1 — branch and scaffold

- `git checkout -b config/toml-consolidation`
- Create `myapp/config/` package if it doesn't exist (`__init__.py`).

Checkpoint: `git status` shows the new package; `python -c "import myapp.config"` succeeds.

### Step 2 — write the loader

Write `myapp/config/loader.py`:

```python
"""Settings loader. Prefers config/settings.toml; falls back to legacy JSON."""
from __future__ import annotations
import json
import tomllib
import warnings
from pathlib import Path
from typing import Any

CONFIG_DIR = Path("config")
TOML_PATH = CONFIG_DIR / "settings.toml"

_warned: set[str] = set()


def deep_merge(base: dict, overlay: dict) -> dict:
    """Recursive dict merge. overlay wins; lists/scalars replace."""
    out = dict(base)
    for k, v in overlay.items():
        if isinstance(v, dict) and isinstance(out.get(k), dict):
            out[k] = deep_merge(out[k], v)
        else:
            out[k] = v
    return out


def load_settings(env: str) -> dict[str, Any]:
    if TOML_PATH.exists():
        with TOML_PATH.open("rb") as f:
            data = tomllib.load(f)
        if env not in data:
            raise KeyError(f"env '{env}' not found in {TOML_PATH}")
        return deep_merge(data.get("default", {}), data[env])

    json_path = CONFIG_DIR / f"{env}.json"
    if json_path.exists():
        if env not in _warned:
            warnings.warn(
                f"{json_path} is deprecated; migrate to {TOML_PATH}. "
                "Run `python -m myapp.config.migrate` to convert. "
                "JSON support will be removed in the next release.",
                DeprecationWarning,
                stacklevel=2,
            )
            _warned.add(env)
        with json_path.open() as f:
            return json.load(f)

    raise FileNotFoundError(
        f"No config found. Looked for {TOML_PATH} and {json_path}."
    )
```

Checkpoint: `python -c "from myapp.config.loader import load_settings, deep_merge; print(deep_merge({'a':1,'b':{'c':2}}, {'b':{'d':3}}))"` prints `{'a': 1, 'b': {'c': 2, 'd': 3}}`.

### Step 3 — write the migration script

Rationale: lands before the TOML is committed so the TOML in the repo is produced by the same script the operator will run if they're upgrading from a fork.

Write `myapp/config/migrate.py` with the entry guarded by `if __name__ == "__main__":`. Logic:

- Glob `config/*.json`, load each as `{env_name: dict}`.
- Compute `[default]` = keys present in every env where all values are equal (shallow comparison is fine for v1; document the limitation).
- Strip those keys from each env table.
- Write `config/settings.toml` with `[default]` first, then envs in sorted order.
- Use `tomli_w` if available; otherwise emit TOML by hand (it's just `[section]` + `key = value` lines for flat dicts — fine for this project's shape). Choose `tomli_w` if any env has nested dicts.
- `--force` overwrites; without it, refuse if the TOML already exists.

Checkpoint: run against the current JSONs; `diff <(python -m myapp --env=dev --dump-config) <(cat config/dev.json | jq -S .)` is empty (after the dump flag lands in Step 5).

### Step 4 — run the migration, commit the TOML

- `python -m myapp.config.migrate`
- Hand-review `config/settings.toml`: sometimes the auto-extracted `[default]` is too aggressive (e.g. a value is "the same by coincidence" in dev and staging but semantically belongs in the env). Edit accordingly.
- Keep `config/*.json` committed — backwards-compat window.

Checkpoint: `git diff config/` shows the new TOML; JSONs unchanged.

### Step 5 — wire `--dump-config` into the CLI

Add to the existing CLI entry (argparse example; adapt to click if that's what the project uses):

```python
parser.add_argument("--dump-config", action="store_true",
                    help="Print resolved settings for --env and exit.")
# ...after args parsed:
if args.dump_config:
    import json, sys
    settings = load_settings(args.env)
    json.dump(settings, sys.stdout, indent=2, sort_keys=True)
    sys.stdout.write("\n")
    sys.exit(0)
```

Checkpoint: `python -m myapp --env=prod --dump-config | jq .db_url` returns the expected prod URL.

## 5. Open questions

- **Removal version**: the deprecation warning and the `TODO` comment both name a target version. Solo, so pick the next minor bump — confirm that matches your release cadence rather than letting it slip indefinitely.
- **CLI framework**: the dump-flag wiring above assumes argparse. If the project uses click / typer / a custom entry, the step shape stays the same but the syntax differs — verify before writing Step 5.
- **`tomli_w` dependency**: only needed if the migration script handles nested env tables. If the current JSONs are flat (which is typical), skip the dep and emit TOML by hand.
